# 세탁기 표시창의 남은 시간 읽기: 시도해볼 방법

회의용 정리입니다. 목표는 기존 세탁기를 건드리지 않고 표시창의 남은 시간(과 에러 표시)을 읽어 서버로 보내는 것입니다. 시연은 교실용 시연 받침의 TM1637 7세그먼트 표시창으로 합니다.

아직 직접 시험한 것은 없고, 아래 내용은 부품 페이지와 일반적인 지식에 근거한 계획입니다. 확인되지 않은 부분은 그렇게 적었습니다.

## 공통: 카메라를 어디에 둘까

사용자가 표시창을 보는 데 방해가 없어야 하므로 표시창 앞에 무언가를 붙이지 않습니다.

- 패널에서 40~60cm 떨어진 위쪽이나 옆에서 내려다보게 둡니다(높이 20~30cm 정도 위).
- 표시창 면의 수직선에서 20~35도 비스듬히 봅니다. 정면은 빛 반사로 숫자가 뭉개지기 쉽습니다.
- 카메라의 촬영 영역(윈도우)을 패널 부분으로만 제한하면 사람이 프레임에 들어오지 않아 개인정보에도 좋습니다.
- 제품 상자에서 20~30cm 높이의 기둥을 세워 카메라를 달고, 기둥은 3D 프린트로 만듭니다(docs/product-exterior.svg).

공통 설정 메모(시험 때 확인):

- 초점: OV2640 렌즈를 돌려 맞춥니다. 처음에는 먼 곳에 맞춰져 있을 수 있습니다.
- 노출: LED 표시창은 자동 노출에서 번집니다. 수동으로 낮춥니다.
- 해상도: 40~60cm 거리에서는 UXGA(1600x1200)가 안전합니다. 20초에 한 장이면 충분합니다.

## 방법 1. 카메라 + 클라우드 비전 AI (기준안)

ESP32-CAM이 JPEG를 서버로 보내고, 서버가 비전 모델에 "남은 시간(분)을 JSON으로"라고 시킵니다.

- 장점: 7세그먼트든 LCD든 똑같이 동작하고, 에러 코드도 같은 사진에서 읽을 수 있습니다. ESP32 코드가 가장 단순합니다.
- 단점: AI API 호출 비용과 지연(수 초)이 있고, 표시창이 어두우면 오독이 늘 수 있습니다.
- 시험: 같은 위치에서 사진 수십 장을 보내 정답률을 셉니다. 오독 방지로 범위를 벗어난 값, 직전보다 갑자기 늘어난 값은 버립니다.
- 주의: OpenCode Go 구독은 코딩 에이전트용이라 앱이 사진을 계속 보내는 용도에는 쓰지 않습니다. 개발 시험에만 쓰고, 실제 앱은 일반 API 키를 씁니다. 공급자는 환경변수로 바꿀 수 있게 만듭니다.

## 방법 2. 카메라 + 고정 영역 세그먼트 밝기 판독 (AI 없음)

카메라 위치를 고정하고, 사진에서 각 자리의 7개 획 위치의 밝기만 보고 숫자를 판단합니다.

- 장점: API 비용이 없고 빠르며, 서버나 ESP32 어디서든 돌릴 수 있습니다.
- 단점: 7세그먼트 LED일 때만 됩니다. 카메라가 조금만 움직여도 위치를 다시 맞춰야 하고, 조명 변화에 민감합니다.
- 시험: 처음에 한 번 "각 획의 위치"를 찍어 두는 보정 화면을 만들고, 밝기 문턱값을 정합니다.
- 활용: 방법 1이 막히거나 비용이 걱정될 때의 대안으로 쓰고, 두 방법의 결과를 비교해 교차 검증도 할 수 있습니다.

## 방법 3. 카메라 + 로컬 숫자 인식 모델

ESP32 또는 서버 안에서 작은 모델로 숫자를 읽습니다. 계량기 숫자를 ESP32-CAM으로 읽는 오픈소스 프로젝트가 있는 것으로 알고 있습니다(프로젝트 이름과 7세그먼트 지원 여부는 확인하지 못했습니다).

- 장점: API 비용이 없고 오프라인에서도 동작합니다.
- 단점: 모델 준비와 학습 데이터가 필요하고, 위치 보정이 필요합니다. 우리 일정에 비해 부담이 클 수 있습니다.
- 시험: 먼저 위 오픈소스 프로젝트가 7세그먼트를 지원하는지 찾아봅니다. 지원하면 설정만으로 되는지 확인하고, 아니면 접습니다.

## 방법 4. 포토트랜지스터 어레이 (직접 제작)

7세그먼트의 각 획 위에 빛 센서를 하나씩 붙여 켜짐을 읽습니다(4자리면 28개).

- 장점: 카메라와 AI가 필요 없고 반응이 빠릅니다.
- 단점: 센서가 패널을 덮어 사용자가 읽기 어렵고, 위치 맞추기가 까다롭고, 선이 많고, 주변 조명에 영향받습니다. LCD는 스스로 빛을 내지 않아 쓸 수 없습니다.
- 판단: 주제("기존 세탁기를 건드리지 않고 붙인다")와 맞지 않아 시연 설명이 약해집니다. 시험은 하지 않는 쪽을 추천합니다.

## 방법 5. 표시 드라이버 통신선 읽기 (참고용)

표시창을 구동하는 칩의 통신선(예: TM1637의 CLK/DIO)을 ESP32가 읽어 숫자를 그대로 해독합니다.

- 장점: 가장 정확하고 가볍습니다.
- 단점: 세탁기를 열어 기판에 연결해야 해서 학교 세탁기에는 쓸 수 없고, 제품마다 칩과 프로토콜이 다릅니다. 시연 받침에서는 숫자를 우리가 이미 알고 있어 의미가 없습니다.
- 판단: 사용하지 않습니다. "가능은 하지만 기존 설비를 개조해야 해서 택하지 않았다"고 설명하는 용도로만 씁니다.

## 비교

| 방법 | 비용 | 기존 세탁기 개조 | 정확도 기대 | 구현 부담 | 추천 |
|---|---|---|---|---|---|
| 1. 클라우드 비전 AI | 호출 비용 | 없음 | 높음(시험 필요) | 낮음 | 기준안 |
| 2. 세그먼트 밝기 판독 | 없음 | 없음 | 보통(보정 필요) | 중간 | 대안·교차 검증 |
| 3. 로컬 숫자 인식 | 없음 | 없음 | 모름 | 높음 | 시간이 남으면 조사 |
| 4. 포토트랜지스터 | 부품비 | 패널을 가림 | 보통 | 높음 | 안 함 |
| 5. 통신선 읽기 | 거의 없음 | 필요 | 높음 | 중간 | 안 함 |

## 시험 순서(부품이 오면)

1. ESP32-CAM에 `CameraWebServer` 예제를 올려 영상으로 거리, 각도, 초점을 잡습니다.
2. TM1637에 임의의 숫자를 띄우고, 위치를 고정해 사진 30~50장을 찍습니다.
3. 방법 1로 읽어 정답률을 셉니다(조명이 다른 경우도 포함).
4. 정답률이 낮으면 방법 2를 붙여 비교합니다.
5. 정한 거리와 각도를 3D 받침 담당(B)에게 넘깁니다.

## 회의에서 정할 것

- 카메라를 먼 위쪽에 두는 방식으로 갈지(추천), 다른 설치 방식이 필요한지.
- 방법 1을 기준으로 하고, 방법 2를 대안으로 둘지.
- AI API 키를 누가 만들고 관리할지(앱이 쓰는 것은 일반 API 키).
- 실제 기숙사 세탁기 표시창 사진을 구해 표시창 형태(7세그먼트인지 LCD인지)를 확인할 사람.
